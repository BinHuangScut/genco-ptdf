# Methods and conventions

## Classical AC derivative

Let x=[theta(PV,PQ), |V|(PQ)] in radians and p.u. At a converged operating point,
F(x)=[Pcalc-Pspec at non-reference buses, Qcalc-Qspec at PQ buses]=0. For a balanced
bus-injection transaction vector d and physical MW transfer t:

```
J = dF/dx
J dx/dt = [d(nonref)/baseMVA; zeros(PQ)]
K = d real(S_from_pu)/dx
H_d = baseMVA * K * solve(J, [d(nonref)/baseMVA; 0])
```

Static DataKit Ybus/Yfrom/Yto include resistance, line charging, taps, phase shifts
and bus shunts. pandapower PYPOWER `dSbus_dV` and `dSbr_dV` provide analytic partials.
The Jacobian is rebuilt **after convergence**, not reused from the previous Newton
iteration. A sparse LU factorization is shared across all right-hand sides.
The implementation directly calls `pandapower.pypower.newtonpf` with the cached
DataKit admittance matrix and empty DC/FACTS device tables;
an independent `pandapower.runpp(algorithm="nr", trafo_model="pi")` comparison
checks the same fixed-control voltage solution. No voltage-dependent load or
reactive-limit bus switching is used.

The delivered data were initially generated by an equivalent sparse Newton loop
using pandapower analytic kernels. Every stored base state and full Jacobian label,
and every paired state's power-balance residual, are checked against the final
pandapower implementation in `results/validation/pandapower_dataset.json`.
Fresh generation uses pandapower directly. This solver alignment does not change
training labels or checkpoints. PF-plus-Jacobian timings are remeasured using the
final solver.

Voltage magnitude and angle are fixed at the reference bus; PV magnitude is fixed.
All Qd, other scheduled Pg, taps and phase shifts are fixed for each transaction.
Reference Pg and controlled-node Qg are outputs, not imposed constraints. Losses
make total incremental reference generation differ from the requested balancing
withdrawal. This is intentional. The AC sensitivities at an operating point with
limit violations remain mathematical fixed-control sensitivities; they are not
claims about the controller-switched operating system.

The complete matrix has one non-reference injection column per bus, PV then PQ,
balanced at the reference. A transaction matrix D is recovered by linear
combination of that basis. Branch output is from-end active power in MW, so H is
MW/MW. Branch losses mean from-end and negative to-end derivatives need not agree.
DC uses the static 1/(x*tap) susceptance network and neglects resistance/losses;
fixed phase-shift constants disappear from its derivative.

## Inputs, dispatch and data

Corrected PGLib IEEE 14/118 files come from the pinned DataKit repository. A
project-specific uniform sampler applies the requested load ranges to DataKit
`Network` objects. Pd and Qd have independent local multipliers. Scheduled generator
Pg uses the base Pg shares normalized to total Pd plus a fixed 3% loss allowance.
PGLib Pg values are initializers rather than balanced schedules; simply scaling
them by load would overload the reference generator. The reference Pg input is ignored
by both PF methods. These samples are not the official DataKit OPF dispatch dataset.

At a PV bus with generators of positive Pmax, an injection perturbation is allocated
among those generators in proportion to Pmax. At other non-reference buses it is
implemented by reducing Pd, with Qd held fixed. A zero-Pmax synchronous condenser
is not used as a source. Multiple generators at one bus share one specified bus
injection; the weights and original bus IDs are recorded in the manifest. Uniformly
select up to 16 unique source-PV → positive-load-PQ transfers (IEEE14 has fewer
available distinct source/sink pairs). Two are sampled per base point for training
secants; all fixed query transfers are used for held-out evaluation.

Each base point and its eight perturbation states (2 transfers × 2 steps × 2 signs)
share a group and split. There are 2000 training, 400 validation, 400 test and 200
higher-load points per grid. Failed base/perturbation solves are logged and replaced;
voltage, aggregate controlled-bus Q, and branch MVA limit violations are retained
and counted, at base points and all stored perturbations. The +5 MW held-out
transaction test also saves its limit flags separately. Negative active-load perturbations are allowed as mathematical net
injection coordinates. This study covers two fixed topologies only.

## Neural model and training

Use the official Small/seed0 per-grid weights and normalization parameters. Save
the given voltage setpoints before masking, then unmask reference Vm in addition
to the official known PF inputs. All unknown quantities are zeroed; true solved
voltage is used only as a target. No unknown voltage labels are inserted into the
input graph. This adapter is identical for frozen initialization and both fine-tunes.

Training uses AdamW (lr=1e-4, default betas, eps=1e-8, weight_decay=0.01), gradient
norm clipping at 1, float32, 8 base groups plus their selected +/- states per update,
at most 100 epochs, patience 10. Each seed has the same group order and perturbation
choices in both arms. Ordinary PF sees the same additional state labels as response
training. The loss is the original 0.9 masked voltage MSE + 0.1 layered physics
residual, plus response weight 1 when enabled. The response term is mean squared
error of from-end MW secants divided by 2h (h=0.1 or 1 MW), over all branches.

CUDA graph execution retains the unchanged upstream model and a mathematically
equivalent loss with static mask indices. It avoids scalar logging synchronizations
inside the loss. Capture warm-up weights and Adam moments are reset, so preparatory
steps are not counted as training. Double-precision tests compare eager/captured
losses and updates. GPU atomic reductions make float32 runs non-bitwise reproducible;
seed/config/data/weights and all observed metrics are preserved.

Checkpoint selection is based on exact model AD relative PTDF error on all 400
validation operating points and 4 fixed transfer directions. Batched graph JVPs
reduce validation overhead without accessing test points. CUDA graph replay may
also accelerate the fixed validation queries. Its inputs and current weights are
checked against uncaptured AD. Initialization is eligible as epoch 0 if training
does not improve the validation score. Maximum budgets are matched; actual early
stopping epochs need not match. No test-set hyperparameter search is performed.

## Evaluation

Model derivatives differentiate physical MW input coordinates through the GNN,
normalization and branch physics decoder. The public full-matrix API uses block
reverse AD. Held-out transfer matrices use batched reverse-over-reverse JVPs; their
agreement with block reverse AD is tested. Training fits finite secants and does
not construct complete second-order derivative tensors.
For fixed topology/query shape, CUDA graph replay accelerates these JVPs. Accuracy
evaluation and query timing use the same captured implementation; capture and
allocation warm-up is outside the timed region. Full matrices use block reverse AD.

Report per-point MAE, RMSE and relative Frobenius error, signs for |Htrue|>=1e-3,
voltage/flow errors, and the MAE of H*5 MW against the true incremental flow for an
unseen +5 MW transfer. Incremental error excludes the base-state prediction error.
Transactions are evaluated on all 600 test/stress points per model. Complete-basis
errors use the first 16 test and 16 stress points, with the subset explicitly labeled.
Classical labels in the stored full matrix are float32; numerical validation uses
fresh float64 reference derivatives.

Timings load models/networks outside the measured region and include dynamic graph
input preparation and CPU-result transfer. Static matrices, cached DC LU, weights
and graph templates are reused. Classical derivative-only and cold-start PF plus
derivative are both recorded. Neural outputs/derivatives use float32 on GPU, classical
methods float64 on CPU. Query-matrix benchmarks use the same directions per grid at
batches 1,16,64; complete matrices additionally use batch 1. Each benchmark warms up,
synchronizes GPU completion and records 20 wall-clock repeats and peak allocated
GPU memory. Benchmarks must run without simultaneous training or other GPU jobs.
Both peak allocated and peak reserved GPU memory are recorded, because graph
memory pools can retain reserved buffers between calls.
Grid-specific training jobs may run concurrently; their training wall times describe
the actual run and are not used as exclusive inference-performance measurements.
